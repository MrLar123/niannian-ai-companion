# 05 — 模型变更历程

> 对话大脑从本地到云端的完整演进，每一步都有实测数据与退役原因。

## 总览

```
qwen2.5:7b ──→ qwen3.5-9b ──→ qwen3.5-9b(直连魔搭) ──→ or_proxy 三上游 auto 路由
(10-16 前)      (10-16 夜)      (10-18)                (10-18 凌晨至今)
本地 Ollama     本地 Ollama     云端直连                代理聚合
```

**主线矛盾**：RTX 5050 只有 8GB 显存——3D 渲染、本地 LLM、embed、ASR 四者抢显存。
最终解法 = **大脑全部上云，显存只留给渲染与 embed**。

## 阶段一：qwen2.5:7b（起点，10-16 前）

- Luna 整合包默认配置：Ollama 11434 + qwen2.5:7b Q4_K_M（7.6B）；
- 问题：御姐人设贴合度一般；4.75GB 权重 + Windows+CUDA 禁 mmap，闲置 5 分钟后重载常因内存不足 `exit status 1`；
- 治理手段（当时）：KEEP_ALIVE=-1 钉显存 + 预热线程 + `ollama app.exe` 改 `ollama.exe serve`（app 忽略 OLLAMA_MODELS 是当时最大坑）。

## 阶段二：qwen3.5-9b（10-16 夜）

- **换模型动机**：用户要求升级大脑。
- **num_ctx=2048 才能全显存驻留**：4096 会溢出 1 层（684MiB）到 CPU；2048 + num_gpu=99 → 5.5GB 100% GPU 零卸载（`ollama ps` Forever）。
- **qwen3.5 思考模式大坑**：默认开启 thinking，reasoning 把 max_tokens 耗尽 → content 为空；
  Ollama 的 OpenAI 兼容端点**忽略 think 参数**，只有原生 `/api/chat` 支持 `think:false`
  → `ollama_chat()` 整体重写为原生端点 + think:False + keep_alive:-1。
- 退役原因：仍占 6.6G 显存，3D 页加载后偶发 OOM。

## 阶段三：直连魔搭 Qwen3.5-27B（10-18）

- 27B 云端免费档，质量大幅提升，显存彻底解放；
- enable_thinking:false 关思考，TTFB 0.5s；
- 问题：限流时无兜底，一个上游单点。

## 阶段四：or_proxy 三上游 auto 路由（10-18 凌晨，现行架构）

- **设计**：单文件代理聚合 方舟（主力额度池）→ 魔搭（备援）→ OpenRouter（兜底）；
- **演进 10-19**：方舟 ark api/v3 全量探测 137 模型、实测 17 可用；
- **演进 10-20**：豆包 lite 单模型烧掉 92.7% 额度（463k/500k）暴露单点问题
  → 8 模型额度池 → 全量 17 模型 ≈850 万 tokens；额度熔断（日额度 1800s / RPM 60s / 自愈）；
- **演进 10-20**：usage 记账（stream_options 自动注入）→ 设置页用量条形图；
- **演进 10-20**：auto 低延迟路由（EMA α=0.35），economy 359ms 与 character 420ms 间浮动；
- **演进 10-20**：`/v1/registry` 纯本地注册表（`/v1/models` 会真拉外网 30s 超时，不能当健康探测）；
- **演进 10-21**：人设贴合度实测——`doubao-seed-character` 最贴 VRM 桌宠（带动作描写+隐含关心）；
- **演进 10-23**：**Key 串道事故**——HKCU 里 ARK_API_KEY 与 Plan Key 同值，标准通道全 401，
  桌宠被 OpenRouter 代码模型扮演（输出 "Here's a thinking process:" 人设崩塌）
  → `_resolve_ark_key()` 分离 + UPSTREAM_PRIORITY 改 ark 首位 + 401 不终止整链。
