# 桌宠（小芸/念念）vs WhalePal 对比与优化清单

> 调研对象：github.com/Jessie-1939/whalepal（Electron 37 桌面鲸鱼娘桌宠，2026-10 版本）  
> 对比基准：本机 `D:/LunaAI/xiaoyun/` 当前实现（Flask 8090 + or_proxy 8787 + Ollama bge-m3 + 3D VRM）  
> 方法：拉取 whalepal 的 README / docs/10/13 / `src/main/context/*` 与当前桌宠 `context_engine.py`、`memory_brain.py`、`memory_store.py`、`desktop_app.py` 逐项核对

---

## 一、一句话结论

WhalePal 的壁垒是 **「屏幕理解 + 分层事件记忆 + 克制门控 + 回顾日历」**；念念的壁垒是 **「3D 沉浸 + 全链路语音 + 语义长期记忆」**。  
两者错位竞争——念念应在**不丢掉语音/3D 优势**的前提下，补齐「情境感知」与「活动回顾」两大短板，并把主动搭话门控做得更像「陪伴而非指挥」。

---

## 三、需要优化的点（按优先级）

### P0 · 屏幕/活动感知管道（最大短板）

- **问题**：念念的情境引擎对「用户在做什么」完全盲。状态只按时钟走，不知道用户在编码、开会还是看视频。
- **做法**（复用 whalepal 思路，成本可控）：
  1. 采集：`engine.js` 的「截屏 → `dhash.js` 感知哈希窗口去重（阈值 4 / 窗口 6）→ 画面未变则把间隔累加成当前活动 `durationMs`」整套搬过来。
  2. 云端理解：走现有 `or_proxy` 的视觉模型（qwen-omni / doubao-omni 都支持视觉输入），复用 `analyzer.js` 的 `ANALYZE_SYSTEM` 与 JSON 契约（activity/category/isWorking/signal/speak/entities/topics/note）。
  3. 离线降级：无 Key / 失败 → 直接用 `analyzer.js` 的 `RULES` 关键词表按前台窗口标题+进程名分类，保证状态联动不空转。
  4. 下游收益：a) 姿势/气泡随活动变（写代码→调试态、开会→会议态、部署→发布态）；b) 屏幕报错→沮丧反应、完成→庆祝；c) 工作态自动闭嘴。

### P1 · 活动事件流 + 今日回顾

- **问题**：念念只有「关于你的事实」语义记忆，没有「你做了什么」的时序记录，答不了「我刚才在干嘛 / 今天干了什么」。
- **做法**：在 `memory.db` 增一层 events 表（ts/date/time/app/activity/category/isWorking/durationMs），承接 P0 的分析结果；复用 whalepal 的 L1 每日摘要(生成一次缓存) + L1.5 实体(现算) 思路，挂一个 `/api/context/today` 与「今日回顾」浮层。事实记忆(你是谁)与事件记忆(你做了什么)并存，不互斥。

### P1 · 主动搭话门控补全

- 补「安静时段静默」（默认 23–6，可配）——与念念现有深夜催睡并不冲突，可把催睡做成安静时段里**唯一的**关怀类开口，其余主动搭话静默。
- 补「未回应停止追问」：发出主动消息后 N 分钟无互动（点/拖/问都算），最多补一次「在吗」，之后安静直到用户先互动（whalepal 的 `TIMEOUT_SIGNAL`）。
- 补「值不值得说」门控：把屏幕观察/主动搭话的开口权交模型 `speak` 字段，减少无谓开口，落实「陪着不是指挥」。

### P2 · 出网白名单 + 隐私红线

- 在 `or_proxy.py` 加一个出站域名白名单校验（借鉴 `net.js`），只放行用户配置的模型端点；非白名单地址直接拒绝，并留审计日志。
- 给记忆抽取 / 屏幕理解的提示词加隐私红线（不复述密码/密钥/金额/聊天原文），与 whalepal 对齐。
- 当前桌宠本地化已比 whalepal 彻底，这条是「制度化」而非「补课」。

### P2 · 省电 / 降载模式

- 3D 常驻 GPU 是事实代价。给低配机/笔记本加可选项：待机降渲染帧率、关闭眼神追随计算、降低 WebView 分辨率。念头的 idle 分支已分呼吸/dance，可叠加「节能档」。

### P3 · 可视化设置面板 / agent 联动（锦上添花）

- 参考 whalepal 的 Liquid Glass 设置页，把现有的托盘切换升级为完整 GUI（陪伴/模型/数据/回顾）。
- 可选：把 or_proxy 的「后台 brain 在想什么」通过本地回环推给桌宠，做成 whalepal 的 DSH 桥接式「真状态」呈现（思考中/调用工具中/报错）。

## 四、念念已领先、保持的点（别动）

1. **全链路语音**：TTS 豆包 2.0 + ASR 豆包流式 2.0 + 口型同步 + 时序铁律——whalepal 路线图才有。
2. **3D 沉浸**：VRM + 眼神追随 + 戳一下挤压物理，表现力远超 2D 立绘。
3. **本地化语义长期记忆**：Ollama bge-m3 向量 + FTS5 RRF，比 whalepal 的纯 JSONL 语义召回更强。
4. **本地优先部署**：不依赖 Electron 下载与远程模型，隐私基线更高。

## 五、落地建议（可复用 whalepal 的具体代码）

- 去重：`dhash.js` + `engine.js` 的哈希窗口（阈值 4 / 窗口 6）——直接搬。
- 离线分类：`analyzer.js` 的 `RULES`（13 类关键词表）——直接搬，补中文应用名。
- 云端理解：`analyzer.js` 的 `ANALYZE_SYSTEM` + `normalizeCloudResult` 契约——改 baseUrl/auth 接 or_proxy。
- 门控：`proactive.js` 的 9 层门控表——抽成配置，注入 `context_engine.py`。
- 记忆分层：`summaries.js`(L1 缓存) / `entities.js`(L1.5 现算) / `store.js`(L2 events) —— 映射进 `memory_store.py`。

> 注意：whalepal 用云端 VLM 做主证据，念念已有本地 embedding 与本地 LLM 池，  
> 可考虑「活动分类本地轻模型先行、云端仅在需要看画面细节时调用」的混合策略，进一步压低成本与出网面。
