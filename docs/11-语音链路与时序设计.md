# 11 — 语音链路与时序设计

> 全双工语音的完整状态机。这是项目踩坑最多（自听死循环五轮）也沉淀最多铁律的模块。

## 状态机

```
off ──start──→ listening ──VAD判完──→ pending ──consume──→ model ──回复完──→ playing
                 ▲                                                        │
                 │                    resume(委派后) / 收尾闸到点           │
                 └──────────────────────── wrapping ←──────────────────────┘
```

| 状态 | 含义 | 麦克风 |
|---|---|---|
| listening | 在听你 | **开** |
| pending | 转写完成待消费 | 关 |
| model | 等大脑 | 关 |
| playing | 她在说 | **关**（真关：pause stream + drop queue） |
| wrapping | 0.8s 收尾缓冲 | 关 |

## 五层自听防护（每层都是一次真实事故的产物）

| # | 防护 | 对应事故 |
|---|---|---|
| 1 | 页面周期上报真实时长 `audio.duration`（`/api/voice/playing {seq,dur}`） | MP3 字节估算偏短 40%+ → 她没说完就开麦 |
| 2 | resume 在 busy 下委派（delegated），开麦由收尾闸 `start+dur+0.8` 决定 | 页面谎报"播完"（autoplay 拦截） |
| 3 | 播放期**真关麦**（两种模式都 `_pause_stream() + _drop_queue()`） | vad 模式只改状态不关流，积压块被当新输入 |
| 4 | PLAYBACK 每轮 do_chat() 清零 | 读到上一条记录 → 兜底瞬间成立 → 页面还没播就开麦 |
| 5 | 回声过滤 `_looks_like_echo()` + LAST_REPLY_GUARD | 转写文本与上条回复高度重合时丢弃 |

**量化教训**：她的音箱回授 0.0023~0.0112，用户说话起点 ≈0.0023——
任何"还能让用户正常说话"的阈值都挡不住回授。**自听只能靠时序解决，抬阈值无用。**

## VAD 设计

```
阈值 = max(下限, 噪声底 × K)
  下限 XIAOYUN_ASR_THR（默认 0.0010）
  K    XIAOYUN_ASR_NOISE_K（默认 1.3，噪声底自适应：安静时更灵敏、吵时收紧）
```

- 噪声底双向自适应更新（旧版只在 rms<thr*0.6 时更新——高增益麦卡死、低增益麦十几秒才降）；
- 数字静默告警：心跳 peak<1e-5 标注（区分"环境安静"与"设备没出数据"）；
- 设备选择 `XIAOYUN_ASR_INPUT` 按名字子串；**USB 音响采集端点会回环系统播放，绝不能当输入**。

## ASR 三通道

```
auto = volc(流式WS,最快) → baidu(REST dev_pid=1537) → whisper(本地CPU int8)
```
- whisper 质量门：log_prob / compression_ratio / no_speech / repetition_penalty 四道 +
  temperature 0→1 逐级回退 + 幻觉黑名单（initial_prompt 回显是教科书级幻觉，已换成自然口语 prompt）；
- 会话代际：每次 start `gen+=1` 开新 worker，旧 worker 发现代际不符退出（防双实例抢队列）；
- 端口独占：`allow_reuse_address=False`（Windows 允许双绑同端口被轮流应答——幽灵行为）。

## 流式 TTS 播放

- 豆包裸 PCM s16le 24kHz（免解码）；边收边播 WebAudio 队列；
- AudioContext 必须在用户点击同步栈内 resume（否则静音无报错）；
- 壳启动参数 `--autoplay-policy=no-user-gesture-required`；
- 播放权 LAST_CLAIM：同一 seq 只给一个页面（双开窗不会双声）；
- 收音恢复三判据：`start+dur+0.8` 到点 / 上报静默 2s / 上限 120s 硬顶。

## 口型同步（双通道）

| 通道 | 适用 | 原理 |
|---|---|---|
| audio 元素型 | 整段播放 | `audio.currentTime` + 20924 字拼音字典逐字对齐 + mp3 RMS 包络找语音段 |
| 流式型 | WebAudio 队列 | 每块 PCM 到达按 20ms 帧算 RMS，播放头落在第几帧取第几帧（**与实际发声逐帧对齐，不预测**）；元音按 0.22s/字节拍推进（等总时长出来再等比映射会口型回跳） |

## 相位可视化

`_voice_phase()`：idle → waiting_play（回复好了等开口）→ playing（🔊 正在说 Ns）→
wrapping（快好了…，0.8s 缓冲）→ idle。UI 与后端状态机同源，杜绝"卡在准备开口"的假死观感。
