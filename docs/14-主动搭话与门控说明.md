# 14 — 主动搭话与门控说明

> 她什么时候会自己开口、什么时候闭嘴。"为什么不说话"的完整判定链。

## 触发源（谁能让她主动开口）

| 源 | 模块 | 例 |
|---|---|---|
| 情境引擎（时段） | context_engine | 早晨问候、傍晚关心、深夜催睡 |
| 屏幕感知（活动） | perception → _speak_proactively | 报错安慰、完成庆祝、有趣观察（note） |
| 屏幕感知（建议） | 模型 speak 字段 | "值得说才说" |
| 长时间无互动 | idle 900s | 轻声搭一句 |

## 门控判定链（按序短路）

```
主动开口请求
 ├─ 她正在说话（busy）？ → 放弃
 ├─ 你正在说话（listening/pending）？ → 放弃
 ├─ 距上次主动开口 < MIN_GAP(600s)？ → 放弃
 ├─ 深夜（凌晨档）？
 │    └─ 是 → 意图池只含催睡；工作态也放行（关怀例外）
 ├─ 工作态（isWorking）且非关怀类？ → 放弃
 ├─ 模型 speak=false（不值得说）？ → 放弃
 └─ 全过 → _publish_reply() 发布（走 SEQ/GUARD/PLAYBACK 三件套）
```

## 各时段意图池

| 时段 | 意图 | 例 |
|---|---|---|
| 早晨 | 晨间问候 | "起了？粥在锅里。" |
| 中午 | 午间关心 | "别又对付一口，点个外卖也行。" |
| 傍晚 | 傍晚搭话 | "今天还算顺吗？" |
| 晚上 | 闲聊/关怀 | "别刷太晚。" |
| **凌晨** | **催睡（唯一）** | "我陪着你，但你得睡了。" |

设计依据：用户熬夜是真实痛点 → 深夜的"关怀密度"反而最高，但**话题宽度**最窄。

## 未回应处理（待补，whalepal P1）

- 当前：主动消息无回应不追问（不主动补发）；
- whalepal 方案：N 分钟无互动最多补一次"在吗"，之后安静直到用户先动——按其清单补入。

## 与对话的关系

- 主动开口的消息**进入历史**（HISTORY），你回应时她有上下文；
- 主动开口的音频走同一 TTS/播放/收音链（`_publish_reply()` 唯一出口——时序铁律第 3 条）；
- 你在说话时她听到一半想搭话 → busy/listening 硬闸拦下，永不抢话。
