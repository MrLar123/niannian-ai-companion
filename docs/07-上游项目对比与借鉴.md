# 07 — 上游项目对比与借鉴

> 三个关键上游项目（AI-Vtuber / WhalePal / 其他）的经历、取舍与优劣势全记录。
> 逐项核对表见 `xiaoyun/docs/whalepal对比与优化清单.md`。

## 1. Ikaros-521/AI-Vtuber（Luna 整合包）——起点

**是什么**：B 站直播 AI 主播框架（Live2D + 弹幕/语音交互 + 多 LLM 接入），本项目从其 20240229 整合包起步。

### 经历
- 10-16 直接以 `app/AI-Vtuber-20240229` 为运行基座：config.json 做配置中心（chatgpt.preset 人设 / openai.api 指向 LLM / edge-tts 音色），Live2D 目录做静态资源，Miniconda 做运行时；
- 桌宠化只写了精简层 `xiaoyun/`（desktop_app + xiaoyun_server），**没有改上游主程序**（main.py / 8081 控制台从未启动）。

### 借了什么
| 借鉴 | 现状 |
|---|---|
| config.json 配置中心结构 | 沿用至今（模型选择双写 openai.model + chatgpt.model） |
| Live2D 静态资源（Hiyori 等 14 模型） | /desktop 页保留可用 |
| preset（人设文本）机制 | 演化为 19 套 JSON 人设体系 |
| Miniconda 运行时 | 后端 python 3.10.11 至今 |

### 优劣势评价
**优势**：开箱即用的 Live2D 链路与配置中心，让桌宠一天就跑起来。
**劣势**（为什么最终只当"资源包"）：
1. 面向直播场景——弹幕接入、B 站 API、chatterbot 对桌宠全是死重；
2. 网页形态，无法透明置顶；
3. 单一 LLM 接入，无多上游路由/熔断；
4. 代码为过程式大文件，改造成本高于重写（本项目 90% 代码自研）。

**结论**：保留其 config.json 契约与 Live2D 资产，主程序完全旁路。这也是"精简层"架构的由来。

## 2. Jessie-1939/whalepal——设计参考（MIT）

**是什么**：Electron 鲸鱼娘桌宠，壁垒是「屏幕理解 + 分层事件记忆 + 克制门控 + 回顾日历」。

### 经历
- 感知管线设计阶段（10-19~10-20）逐文件读了它的 `src/main/context/{dhash,engine,analyzer,proactive,summaries,entities,store,net}.js`；
- `perception.py` 头注明确署名借鉴来源；README 致谢列出；
- 它的 README/docs 体系（13 篇编号文档）也是本项目 docs/ 目录结构的参考范本。

### 借了什么（具体到行为）
| 借鉴 | 落地方式 |
|---|---|
| dhash 9x8 + 汉明阈值 4 | perception.py `SIMILARITY_THRESHOLD = 4`（同值，注释注明取其 2 与 6 之间） |
| 截屏去重窗口 + duration 累加 | engine 骨架照搬，装进 Flask 后台线程 |
| 13 类活动 JSON 契约 | `ANALYZE_SYSTEM` 提示词逐字段对齐（activity/category/isWorking/signal/speak/detail/note） |
| 离线降级 RULES 关键词分类 | classify_window() 同思路（标题+进程名） |
| "值不值得说"speak 字段 | 主动搭话开口权交给模型，减少无谓开口 |
| 深夜劝休息 | 演化为凌晨催睡意图池（"关怀不是闲聊"） |

### 没借什么（及原因）
| 未借鉴 | 原因 |
|---|---|
| Electron 架构 | 与 pywebview+Python 后端路线冲突；200MB 运行时不值 |
| PNG 序列帧 2D 立绘 | 用户要 3D 沉浸（VRM 物理与眼神追随是卖点） |
| JSONL 纯文本记忆 | 已有 SQLite FTS5 + 向量 RRF，语义召回更强 |
| 代码层出网白名单 net.js | **待补**（P2）：or_proxy 多上游无硬白名单，是双方差距最大项 |
| 日历热力图 | 待补（P3）：当前只有今日聚合，无跨天热力图 |
| 9 层主动搭话门控 | 部分补齐（4 层 + 深夜意图池），安静时段静默/未回应停止追问待补 |

### 优劣势对比（8 维度速览）
| 维度 | WhalePal | 念念 | 优劣 |
|---|---|---|---|
| 屏幕感知 | ✅ | ✅ 已对齐 | 持平 |
| 记忆 | JSONL 文本分层 | FTS5+向量 RRF+四操作消解 | 念念胜 |
| 语音 | 路线图 | 流式 TTS 0.45s + ASR 三通道 + 口型双通道 | 念念胜 |
| 角色表现 | 2D PNG 序列（CPU≈1%） | 3D VRM（GPU 常驻） | 各有取舍 |
| 门控 | 9 层 | 4 层+深夜池 | whalepal 胜 |
| 隐私制度化 | 代码层白名单+审计脚本 | 数据本地化彻底但无白名单 | whalepal 胜 |
| 回顾 | 日历热力图+时间线 | 今日聚合+设置页 | whalepal 略胜 |
| 设置 UI | Liquid Glass 面板 | 托盘+网页设置页 | 持平 |

**一句话总结**：错位竞争——它赢在"制度化的克制"，我们赢在"沉浸与语音"。感知管线已融合，门控与白名单按其清单逐步补。

## 3. 其他参考项目

### mem0 / Letta（记忆设计）
- 借**四操作消解**：记忆抽取时模型先判定 ADD/UPDATE/DELETE/NOOP，避免事实无限堆积；
- 没直接用库：依赖重（向量库+编排），自研 memory_brain.py（411 行）只保留设计。

### StreamVox（本地流式 TTS SDK）
- 评估后**否决**：wheel 需 py3.12 sidecar；现架构整段播放拿不到流式收益；Qwen3 克隆无 speed/emotion 参数；
- 但**借了设计**：句级切段 text_processing.py 思路进入 tts_stream.py；"借设计不借代码"是本项目对外部 SDK 的标准姿势。

### 腾讯混元 3D / Avaturn（3D 资产，外部依赖）
- Hunyuan3D-2mini（单图）/ 2mv（四视图）本机部署，产出全部模型资产的白模与贴图；
- Avaturn 免费网页导出（经 Discord bot 解锁），产出 187 morph 照片脸；
- 局限实证：单图管线 512² 输入脸只占 42px → 全身生成脸必然平 → 头身分离是唯一解。

### GPT-SoVITS（本地 TTS 克隆）
- 保留引擎位（切本地音色时按需拉起，空闲 900s 自动释放）；
- 本包未含（10G 权重）：BERT 必须 GPU 加载（fp32 CPU 会段错误）是实测硬约束。

### MineContext / screenpipe / OpenAdapt（感知领域调研）
- whalepal README 已对照过三家；本项目采纳其结论——**文本记忆优于截图存档**（3MB/月 vs 124MB/月），截图只算 dhash 即弃。

## 4. 借鉴纪律（沉淀为规则）

1. **署名**：凡借鉴设计（哪怕只是阈值数字），头注+README 致谢双重标注；
2. **借设计不借代码**：外部 SDK 只抄架构思想，不引依赖（StreamVox/mem0 均如此）；
3. **实测优先**：上游"宣传能力"与本机可用性分离（Avaturn 宣传 ARKit blendshapes，免费导出实测没有，第三版才有）；
4. **契约对齐**：借鉴 JSON 契约时逐字段对齐并注释来源，方便上游演进时 diff。
