## 二、探测方法（三层，逐层收窄）

| 层 | 做法 | 判据 |
|---|---|---|
| 1. 路径来源 | 抓 `docs.volcengine.com/docs/doubao-voice/*` 的 25 个页面 HTML（SSR，正文在源码里），正则扫 `openspeech.bytedance.com/...` | 避免猜 URL |

## 五、两个「看起来能通、其实不通」的坑

### 5.1 录音文件识别（`volc.seedasr.auc`）

resource 校验通过（不报 45000030），看起来可用，但提交任务时：

```
http=400 code=45000000
acquire failed err:call ark get status code:400
code:InvalidParameter.UnsupportedHarnessKey
message:The X-Inner-Vendor-Key header is missing or does not match any
        registered Harness vendor.
```

Plan 网关把请求转给 ark 时需要给这个 resource 打 vendor 标签，`volc.seedasr.auc` 没配 →
**服务端配置缺失，客户端无解**。已排除 `X-Api-Sequence` 头干扰（带/不带结果一样）。

### 5.2 双向流式 TTS 的帧格式（踩了 3 次才通）

火山 v3 二进制协议的字段布局是**按事件类型变化**的：

```
header(4) + event(int32, 大端)
          + [session_id_len(4) + session_id]   ← 只有 Session 类事件(>=100)有
          + payload_size(4) + payload
```

| 错误写法 | 服务端报错 |
|---|---|
| Session 事件也带 sid 字段、Connect 事件不带 → 反了 | `declared body size does not match actual body size: expected=0 actual=16` |
| 所有帧都不带 sid | `parse payload size failed: body too short`（把 payload_size 误读成 sid_len） |
| 发完 TaskRequest 不发 FinishSession | 只回 350 SentenceStart，之后**永久静默**（服务端在等更多文本） |

正确时序：`1 StartConnection → 50` → `100 StartSession → 150` →
`200 TaskRequest` **紧接** `102 FinishSession` → `350 → 352×N → 351 → 152`。

## 六、对 LunaAI 的可用结论

### 现在就能用（Plan Key，不额外花钱）

| 能力 | 端点 | 实测 |
|---|---|---|
| TTS（当前桌宠在用） | `/api/v3/plan/tts/unidirectional` | 200 / 27KB / 0.68–0.85s |
| 双向流式 TTS | `/api/v3/plan/tts/bidirection` | 32KB / **首包 607ms** / 总计 1.13s |
| 单向流式 ASR（在用） | `/api/v3/plan/sauc/bigmodel_nostream` | 已投产，约 1.1s |
| 双向流式 ASR | `/api/v3/plan/sauc/bigmodel_async` | 握手 101，数据协议未接 |

**双向流式 TTS 的价值**：可以「边喂文本边收音频」，适合直播/长回复——不用等整句生成完再合成，
首包 607ms 比 HTTP 版的整段返回更早出第一声。桌宠如果要接直播链路，这是首选。

### 需要语音平台 Key 才能用

音频生成（音色克隆/音效）、声音复刻、音色设计、录音文件识别、播客、同传、机器翻译、Seeduplex。
申请入口：<https://console.volcengine.com/speech/new/setting/apikeys> → `VOLC_SPEECH_PLATFORM_KEY`。
`or_proxy` 已支持拿到 Key 后自动切通道（`tts_channel` 从 `plan` 变 `platform`）。

### 明确不要碰

- `/api/v3/auc/*`（录音文件识别）——网关配置缺失，换 resource、换 header 都无解
- `/api/v3/plan/sauc/bigmodel`（v3 新路径）——网关没这个端点，别照文档改

## 附：2026-11-05 后续结论补记

1. 探测时「没有豆包语音控制台 API Key」是当时状态。后续已确认**三套凭证用途**：普通方舟 Key（LLM / 视觉 / 向量）、Plan Key（`/api/v3/plan/*` TTS 与 ASR ws、`/api/plan/v3/*` 生图生视频）、豆包语音控制台 Key（`/api/v3/tts/unidirectional`、`tts/create`）。
2. **双向流式 TTS 帧结构**已实测：header(4B) + event(4B) + [sid_len + sid，仅 event≥100] + size(4B) + payload；**发完 TaskRequest 必须立刻发 FinishSession(102)**，否则服务端永久静默——这是「WS 握手 101 但收不到音频」的头号原因。
3. resource 白名单复核仍只有 `seed-tts-2.0` / `volc.seedasr.sauc.duration` / `volc.seedasr.auc`；录音文件识别 `UnsupportedHarnessKey` 结论不变，别再试。
4. 独立 ASR 模型 `doubao-seed-asr-2.0` 走 WebSocket（Plan Key，wav/16bit/单声道），由 `or_proxy._asr_ws()` 封装，实测比 sauc 快 28~31%。
