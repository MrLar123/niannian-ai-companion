## 1. 情绪旁路与 PMX 表情体检

**目标**：让表情随「他说的话」变化，且 31 套形象都能用。

| 变更 | 落点 |
|---|---|
| 规则层独立真源 | `emotion_rules.py`；`JUDGE_SYS` 与 `tools/emo_probe.py` 的 `JUDGE_SYS_V3` 逐字一致 |
| 判定链路 | `_kick_emotion` 挂 3 处（`_brain_turn` 首行、`_cmd_say`、`_speak_proactively`）→ 规则层 <1ms 先落地 → daemon 跑 judge → `EMO_STATE` → `/api/last` 两分支带 emo |
| 表情写者收敛 | 前端 `Face` 是唯一写者；poke 降级为 overlay(140ms TTL)，治「戳完突然面无表情」 |
| 表情槽位标定 | 7 槽位按日文 morph 名解析；产物 `assets/emo_slots.json`；整改报告 `PMX表情体检报告.md` |

**四个致命坑（都已修）**：
1. 输入必须是**他说的话**——用「她的台词」判定只有 18% 命中；
2. judge 必须带 `thinking:{"type":"disabled"}`——思维链吃光 `max_tokens=8`，`content` 全空却 HTTP 200 全判 none；
3. 模型写死 `doubao-seed-character-260628`，**不能走 auto**；`or_proxy.BASE_FIELDS` 已补 `thinking` / `reasoning_effort`；
4. 模型回 `none` 是**有效结论**，要覆盖规则层，不是失败。

**表情标定铁律**：「笑い」多半是闭眼笑、「にこり」才是睁眼微笑；morph 权重是持久数组，情绪回落必须每帧显式写 0；脸红贴片缺失时用脸材质染色 `__tint` 兜底；探测权重必须等于真机权重；morph→像素不单调要做 AMP_GATE。

**验收**：31 模型 × 8 情绪 = **248 格全达标**，calib 与 audit 双链路一致、噪声 0；`tools.test_emotion_rules` / `test_emo_backend`(58 项) / `tools/emo_e2e.py` / `node tools/face_ab.mjs`。

## 4. 语音指令路由：四类意图与反问闭环

**Phase 1 之后补的三块**：动作 one-shot、ASR 近似反问、指令偏好记忆。

### 4.1 动作 one-shot 与持久选择分离

| | 语音 | 菜单点选 |
|---|---|---|
| 语义 | 播一遍回待机 | 持久切换 |
| 状态 | 内存 `ONESHOT{key,seq,at}`，**不写盘** | `current.txt` |
| 页面 | `playDance(key, oneShot)` → `LoopOnce` + `clampWhenFinished` | `LoopRepeat` |
| 结束 | 渲染循环 `tickOneshot()` 判 `danceAction.time >= clip.duration - 0.02` → `POST /api/motion_done` → 清冷却 | — |

- **seq 递增而非比 key**：同一支舞连说两次 key 不变，靠 seq 才认得出是新请求。
- 结束判定必须放渲染循环；放 2 秒轮询会滞后 2 秒，舞蹈停末帧干站着难看。
- `/api/motion_done` 带 key 校验，旧请求返回 `stale=True`；`stop_motion` 清 oneshot。

### 4.2 ASR 近似：只反问，不执行

**发现的真缺口**：「换成甘兩」（甘雨被听错一个字）原本返回 `None` 直接落闲聊——用户以为换装成功，其实她只是接了句话。根因是两字名为防误伤禁用了近似**执行**（实测「换成甘雨」被比成音色「晓雨」，两者相似度都 0.5），但代价不该是「既不切也不问」。

| 层 | 规则 |
|---|---|
| 执行层 | 两字名阈值 **1.01**（永不可达，直接禁近似）；三字以上 `FUZZ_MIN=0.72` + `FUZZ_GAP=0.06`；闸门 = 换/切动词 + 非问句 |
| 反问层 | 独立 `loose_candidates()`（两字 0.5、最多 3 个候选）；闸门 = 换/切动词 + 非问句 + 残留 ≥2 字 + 至少一个候选 |
| 兜底 | 连一个像的候选都没有 → 安静交还对话（「换成现金」、问句、长句闲聊零打扰） |
| 消歧 | 性格是第四类意图 `switch_preset`；与音色别名重叠（温柔/高冷）**必须带锚点**（性格/人设/人格/脾气）才按人格 |
| 匹配 | `clean_label` 剥「· 时长」保留服装名；`_norm()` 去间隔号；整名 +FULL_BONUS / 拆段只按长度，否则「换成卡芙卡泳装」静默切成基础版 |

**确认闭环**：`CLARIFY_PENDING`(45s) 存候选；用户回「对 / 第一个 / 重报名字」→ 合成一句带精确名字的话**回放给 `_try_voice_command`**（复用原执行链，不复制切换逻辑）。带换/跳动词的新指令先作废 pending 再正常解析，避免「变成甘雨吧」被吞。`/api/chat` 与 `/api/chat_stream` 两条入口都走 `_try_voice_command`。

### 4.3 偏好记忆（Phase 3）

`data/cmd_prefs.json` 记四类 `key→{count,last,label}`，**仅成功执行时累加**，只用于 `_pref_hint()` 排反问候选清单，**不参与任何执行判断**；与 `memory.db` 长期记忆严格隔离（偏好是使用频次，不是用户意图，进执行链会重演误触）。反问清单改为从真实注册表取，删掉写死口味词的旧函数。

|---|---|

| `tools/test_voice_command_wiring.py` | 全部通过：确认闭环、偏好落盘、新指令不被吞、Flask `test_client` 真 HTTP 两入口 |
