# 12 — 记忆介质决策

> 为什么长期记忆是「SQLite FTS5 + 向量 RRF」而不是纯向量库 / 纯文本 / 通用记忆框架。

## 需求画像

桌宠的记忆要同时回答两类问题：
1. **"你还记得我吗"型**（事实层）：养的猫、作息、口味——低频写入、语义召回、跨月留存；
2. **"我刚才在干嘛"型**（事件层）：屏幕感知产生的活动流——高频写入、按时间聚合、7 天滚动。

## 候选对比

| 方案 | 优势 | 否决/取舍原因 |
|---|---|---|
| 纯向量库（Chroma/Qdrant） | 语义召回强 | 引入服务依赖；本机检索量小，杀鸡牛刀 |
| mem0 直接用 | 四操作消解设计成熟 | 依赖重（编排+向量库）；借设计自研（ADR 见 07 文档） |
| whalepal 式纯 JSONL | 零依赖、可读 | 无语义召回（"猫毛过敏"搜不到"我养了只猫"）；无并发写保护 |
| **SQLite FTS5 + 向量 RRF** ✅ | 单文件、零服务依赖、两种召回并存 | 中文需 bigram 索引（已实现）；向量路依赖 Ollama（不可用自动退化纯 FTS5） |

## 实现要点

- **bigram 而非分词**：本机无 jieba，bigram 对检索足够（「美式咖啡」→「美式 式咖 咖啡」，任一片段命中）；
- **RRF 融合**：两组分数不同尺度不可直接比 → Reciprocal Rank Fusion（k=60）；
- **四操作消解**（memory_brain）：新事实先判 ADD/UPDATE/DELETE/NOOP，防"用户养了猫"堆积 20 条；
- **维度卫生**：换 embed 模型必须 `purge_mismatched_vectors(dim)`（bge-small 512 维 → bge-m3 1024 维的教训）；
- **/api/reset 不删长期记忆**：软重置只清对话历史——"她忘了你说过什么"不该等于"她忘了你是谁"。

## 事件层（events_store）

- JSONL 追加写；单段封顶 600s（同一活动不无限累加）；保留 7 天自动裁剪；
- 聚合查询 `/api/context/today`：category 占比 + duration，供设置页与"今天干了什么"问答；
- 与事实层并存不互斥：事件层答"你做了什么"，事实层答"你是谁"。

## 体积实测（whalepal 同口径）

| 介质 | 月增量 |
|---|---|
| 按事件留存截图 | ~124 MB/月（否决） |
| 文本记忆（本实现） | ~3 MB/月 ✅ |

## 情境引擎（context_engine）

- 空闲 900s 触发主动搭话判定；最小间隔 600s；久别问候 180s 窗口；
- 时段意图池：早晨/中午/傍晚/晚上/深夜各有专属意图；**凌晨档唯一意图 = 催睡**（关怀不是闲聊）；
- 工作态门控：isWorking=true 时问候让位（不插嘴），催睡例外放行（分支顺序是实测踩过的坑）。
