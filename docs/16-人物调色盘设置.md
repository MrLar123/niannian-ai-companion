# 16 — 人物调色盘设置

> 每只模型的观感调色系统：四个滑块 + 着色器管线 + 落盘机制 + 当前全部 16 只模型的实测定档值。
> 适用于 PMX 页（desktoppmx.html）；VRM 页另有一套按模型文件名标定的肤色 tint（见 §6）。

## 1. 入口（三种打开方式）

| 入口 | 路径 | 适用场景 |
|---|---|---|
| 右键她 | 右键菜单 →「调参：亮度 / 饱和度…」 | 桌面上直接调（最快） |
| 托盘 | 托盘菜单 → 同名项 | 她被挡住时 |
| 独立预览窗 | `Preview-Pet.ps1 -Model <key> -Tune` 或桌面「桌宠预览」文件夹里的 `看<label>.bat` | 边看单模型大图边调，不影响桌面上的她 |

调参窗是独立的 Chrome `--app` 小窗（`/pmxtune`，330×300，独立 profile PetTune）；
`?tune=1` 也可把面板内嵌进预览页（iframe 复用同一个面板页）。

## 2. 四个滑块与着色器管线

调色在 **片元着色器** 里做（注入 MMDToonShader），四个 uniform 按固定顺序作用：

```
c = clamp((c - 0.5) × uGradeC + 0.5)     ← contrast 对比度：绕中点 0.5 拉伸
c = mix(vec3(luma), c, uGradeS)           ← saturate 饱和度：向灰度插值（1=不动）
c = pow(c, vec3(uGradeG))                 ← gamma：S 曲线压暗的补偿，"层次变多而非变暗"
c = clamp(c × uGradeB)                    ← bright 亮度：放最后，提亮不压高光成死白块
```

| 滑块 | 默认 | 范围 | 作用与经验 |
|---|---|---|---|
| **contrast** | 1.20 | 0.30~3.00 | 绕中点拉伸；＞1.5 会开始丢暗部细节 |
| **saturate** | 1.18 | 0.30~3.00 | 赛璐璐材质对饱和度极敏感，2.0 以上普遍过艳 |
| **gamma** | 0.85 | 0.40~1.60 | **最常用的补偿项**：saturate/contrast 提高后画面整体压暗，靠 gamma 拉回（值越大越亮）；全白模型往 1 附近收，避免高光削顶 |
| **bright** | 1.00 | 0.60~1.60 | 纯明暗倍率；1.45 已能把白衣模型烧白 |

**设计要点**：bright 放在 gamma **之后**是刻意的——提亮时不会顺手把 gamma 拉出来的层次压成一片死白。

## 3. 使用流程（1 秒实时生效）

```
拖滑块 → POST /api/grade {model, params}
       → 后端 GRADE_LIVE 运行期覆盖 + GRADE_SEQ +1
桌面页 700ms 轮询 /api/grade?model=<自己>
       → seq 变了才重设材质 uniform（拖动时她 1 秒内跟着变色，不重载、不打断舞蹈）
点「保存」 → POST /api/grade {save:true} → 合并写进 models/<key>/model.json 的 params
点「复原」 → 清 GRADE_LIVE 回 model.json 值
```

- **不落盘也算数**：GRADE_LIVE 是运行期覆盖层，重启后回到 model.json 存档值——可以先大胆试；
- 保存时**只合并四个颜色键**，model.json 其余字段（label/params 取景参数）原样保留；
- `?grade=0` 可完全关掉调色（A/B 对照原图）；`?model=<key>` 锁死单模型预览；
- 调参只动观感，与动作库/取景参数完全无关（右键菜单里是独立入口）。

## 5. 落盘与取值优先级

```
生效值 = GRADE_DEF(默认) ← model.json params 覆盖 ← GRADE_LIVE(运行期) 最高
```

| 操作 | 落点 |
|---|---|
| 拖滑块（不保存） | 仅 GRADE_LIVE（内存） |
| 点保存 | model.json 的 params 四键合并（其余字段原样保留），并清缓存 |
| 重启后端 | GRADE_LIVE 清空，回到 model.json 存档值 |
| 历史目录（assets/peier） | 存自己的 `assets/peier/model.json`（`_grade_json_path` 支持老目录） |

换模型后端重新扫目录时以 `_dir_sig` 指纹判断，改 model.json 会自动触发清单刷新。

## 6. VRM 页的肤色 tint（另一套体系）

desktopvrm.html 的 VRM 模型**不走四滑块**，走按模型文件名标定的 `SKIN_TINT_TABLE`：
给皮肤材质的 litFactor 乘线性空间暖色 tint（治白底贴图×多灯光=纯白的问题）。

| 模型 | body tint | face tint | 说明 |
|---|---|---|---|
| 小芸.vrm | (0.55, 0.44, 0.32) | (0.60, 0.44, 0.40) | 强暖调（贴图偏冷白） |
| 小芸-jk.vrm | (0.78, 0.66, 0.56) | (0.80, 0.68, 0.62) | 弱档（贴图本身浅暖米色） |
| avaturn_nn.vrm | 全 1 | 全 1 | 照片重建肤色，不需要校正 |
| 未登记模型 | default (0.72, 0.62, 0.52) | (0.76, 0.64, 0.56) | 偏"略白"防发黄 |

- 标定方法：`?tint=r,g,b`（身体）/ `?facetint=r,g,b`（脸）现场标定，标好登记进 SKIN_TINT_TABLE；
- **tint 是线性空间值**（0.55 线性 ≈ 0.77 sRGB——写 0.92 几乎等于没改，是踩过的坑）；
- `?skin=0` 完全关闭；材质名按 GLTF 真实名匹配（VRoid 系 `*_SKIN` 规则），不匹配自动跳过。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 拖了滑块她没变色 | 调参窗的 model 参数与桌面当前形象不一致；或 `?grade=0` 关了调色 |
| 变色了但重启后回去了 | 没点「保存」——GRADE_LIVE 只在内存 |
| 保存后其它参数丢了 | 旧版本 bug，现只合并四色键；若复现检查 model.json 是否被手改过坏结构 |
| 白衣模型一片死白 | bright 顶到 1.6 + gamma 过低；先降 bright 再提 gamma |
| 想看原图对比 | 页面 `?grade=0`；或把四值全调回默认（1.20/1.18/0.85/1.00） |
| 新模型想进调参流程 | 目录放对即可自动发现；首次定档参考 §4 的两条路线（素材亮→压，素材暗→gamma+bright） |
