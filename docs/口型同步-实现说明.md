# 小芸口型同步（方案 B）实现说明

> 目标：让小芸"说话时嘴动起来"，且口型与发音大致对应，而不是单纯一张一合。
> 选型结论：文本 → 拼音 → 五元音口型 + 音频包络时间对齐（不用 AI 反推音频内容，因为我们本来就知道要说什么）。

---

## 1. 为什么不用 AI 视频方案

| 方案 | 适配性 | 结论 |
|---|---|---|
| Wav2Lip / MuseTalk / SadTalker | 只适合 2D 真人图片，逐条生成视频，延迟数秒，抢显存 | 只作为 2D 立绘的可选路线，不用于 3D |
| Rhubarb Lip Sync | 音素时间戳工具，英文准、中文需 `--extendedShapes` 且要手工修 | 可作离线兜底，实时性差 |
| **文本→音素→口型（lighter-sync 思路）** | 与引擎/形象无关，零依赖、实时 | **采用** |

关键便利点：MMD(PMX) 模型自带「あ・い・う・え・お」五个口型 morph，VRM 自带 aa/ih/ou/ee/oh，
Live2D 有 ParamMouthOpenY —— 五个元音口型几乎覆盖中文全部韵母，不需要训练模型。

## 2. 三步原理

1. **文本 → 口型码**：逐字查 `zh-visemes.json`，得到（声母口型, 韵母口型）。
   例：巴 `01`（闭唇→开口）、说 `25`（扁口→圆唇）、我 `35`（撮口→圆唇）。
   口型码：`0`闭唇 `1`开口(a) `2`扁口(i) `3`撮口(u) `4`中口(e) `5`圆唇(o)。
2. **音频 → 语音段**：解码 mp3，按 20ms 一帧算 RMS，找出真正发声的区间（阈值 = 峰值的 10%，
   并合并 <120ms 的碎缝）。停顿不会被塞入口型。
3. **铺时间轴 + 插值**：**onset 锚定**（2026-10-19 升级，替代原纯权重比例铺排）——
   段内检测能量通量峰（3 帧平滑 RMS 的上升沿局部极大），利用"合成文本已知、音节数
   是精确先验"直接取通量最强的 N 个峰（N=音节数，最小间隔 130ms，峰夹回语音段内）；
   前 N-1 个音节的边界由 onset 直接钉住，剩余音节在尾部语音时间里按权重补位；
   无峰（通量趋 0）自动退化为原比例铺排。实测合成脉冲包络 12/12 全中（误差 1 帧），
   平均对齐误差 26ms→12ms；每个音节内部仍按 22% / 78% 切成"声母口型 → 韵母口型"。
   播放时逐帧读 `currentTime`，做 55ms 交叉淡化 + 张嘴 40ms / 闭嘴 90ms 的非对称平滑，
   最后乘以实时音量做门控 —— 小声的字嘴不会张太大。

| `assets/lipsync/sample.mp3` | 测试音频（晓晓音色，"你好呀，我是小芸…"） |

| `tools/test_lipsync.js` | 离线自测：纯逻辑（比例铺排路径） |
| `tools/test_lipsync_onset.js` | 离线自测：合成脉冲包络验证 onset 锚定/欠检补位/退化 |
| `tools/verify_lipsync_cdp.mjs` | 无头 Chrome 实测：解码 + 时间轴 + 逐帧采样 |
| `tools/shoot_mouth.mjs` | 口型形变截图（闭嘴/あ/い/う 对比） |
| `tools/check_pet_page.mjs` | 检查桌宠页是否识别到 5 个口型 morph、有无 JS 异常 |

已接入页面：**`desktoppmx.html`（当前默认形象，PMX/MMD）**
- 脚本标签 + 字典预加载 + `say()` 里 `attach(curAudio, text)` + 渲染循环里写 `あいうえお`。
- 调参：`MOUTH_GAIN = [1.25, 1.75, 1.45, 1.50, 1.35]`（a i u e o 各自幅度）。
- 调试：控制台 `window.__xyMouthOverride = {a:1,i:0,u:0,e:0,o:0}` 可手动摆口型，
  `window.__xyMouthOverride = null` 恢复自动。

## 4. 怎么验证

1. 浏览器打开 `http://127.0.0.1:8090/assets/lipsync/test.html`，点"播放 sample.mp3"，
   五根条应按发音变化（不是随机抖动）。
2. 桌宠页：**重启小芸桌面**（`停止小芸桌面.bat` → `启动小芸桌面.bat`），
   点她说话，观察嘴部。控制台会打 `[lipsync] 字典就绪` 和 `口型同步已挂载`。

## 5. 已知局限

- **2D 立绘**：没有嘴部可动素材，方案 B 无处落地。要么做 2~3 张嘴型差分图（半调），
  要么走 Wav2Lip 类视频生成（重）。当前 2D 页面未接入。
- **Live2D**（`/live2d`，AI-Vtuber 自带页面）：参数名是 `ParamMouthOpenY` / `ParamMouthForm`，
  接入工作量约半天，因页面属于另一套代码，暂未动。
- **多音字**：字典取最常用读音（行/重/了），口型影响很小，可接受。
- **时间对齐精度**：onset 锚定后音节边界误差约 1 帧（20ms 量级，合成包络实测 12/12 命中）；
  仍是帧级精度而非逐音素时间戳（豆包 seed-tts-2.0 实测不支持 enable_timestamp，
  文档标注仅 TTS1.0，而 uranus 音色是 2.0 专属）。观感足够。
  若未来要再进一档，可上本地 Paraformer 强制对齐（文本已知，对齐条件理想）。
