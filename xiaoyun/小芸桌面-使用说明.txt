============================================================
  小芸桌面 · Windows 桌面 AI 女友　使用说明
============================================================

【这是什么】
一个直接贴在你 Windows 桌面上的 AI 女友「小芸」——不是网页，是独立的
桌面窗口：
· 窗口：无边框 + 背景透明，小芸直接站在你的桌面上，挡不住后面的图标。
· 大脑（对话）：本地模型 Ollama + qwen3.5-9b，在你的显卡上运行，
  对话内容不出本机、可离线、不花一分钱。
· 形象：默认是 **3D 立体模型**（御姐：黑色包臀皮裙 + 黑丝 + 高跟鞋，three.js 实时渲染）；
  另保留 2D 立绘版（JK 真人）与 Live2D 版（Haru），三套可切换，见下文第 3 条。
· 人设：高冷御姐型，27 岁。
· 声音：微软 Edge-TTS 在线免费语音（晓晓，温柔女声），需要联网，免费。
· 本项目基于 GitHub 开源项目 Luna AI（Ikaros-521/AI-Vtuber，GPL 免费）。

------------------------------------------------------------
【最简单的用法】
1. 双击桌面的「启动小芸桌面.bat」
   （会自动启动本地大脑 + 后端 + 桌面窗口）
2. 第一次打开后，模型加载需要 10～30 秒，请耐心等一下。
3. 小芸出现在屏幕上（默认右下角）。点她一下打开聊天窗，打字回车发送，
   她会回复并把话说出来（头顶冒气泡）。
   注意：双击后黑窗口会停留一会儿，桌面窗口组件加载需要 15～40 秒，
   请耐心等它走完，不要中途关掉黑窗口。
4. 用完双击桌面「停止小芸桌面.bat」即可关闭（本地大脑仍会在后台）。

★ 关于「本地大脑 Ollama」的重要说明
  Ollama 现在是**后台服务方式运行，没有自己的托盘图标**——
  所以看不到 Ollama 图标是正常的，不代表它没启动。
  想看它到底在不在：右键点托盘里小芸的粉色爱心图标，
  菜单最上面一行会显示「本地大脑(对话): 已就绪 (qwen3.5-9b)」。
  如果显示「未运行」，直接点它下面的「重启本地大脑（不回话时点这个）」即可。

------------------------------------------------------------
【桌面窗口怎么用】
★ 透明模式（默认）
  她完全透明地贴在桌面上，不挡后面的东西，而且是可交互的：
    · 拖动：在她身上按住鼠标，拖到桌面任意位置（不做限制，可以贴边甚至压到屏幕边缘）
    · 点击：点她一下，打开聊天窗口
  原理：透明窗口本身收不到鼠标事件（Windows WebView2 的固有限制），
  所以在她的身体位置额外盖了一层「肉眼看不见但能接收点击」的薄膜，
  点击和拖动都由它接管——外观全透明，操作照常。

★ 互动模式（可选，一般用不到）
  托盘右键 →「互动模式（可拖动/可点击）」，她会变成一张淡粉圆角小卡片。
  这个模式的用处是：当你想确认她的边界在哪、或者觉得隐形点击区不好点时。
  再点一次取消勾选即可切回全透明。

· 聊天：
    · 托盘菜单 →「打开聊天记录」
    · 或者按全局快捷键 Ctrl + Alt + X
    · 或者直接点她一下
  聊天窗口是独立窗口，带完整对话历史，可以正常打字；
  关掉它只是隐藏，不会退出小芸。
· 气泡：她说话时头顶会冒气泡，几秒后自动消失。
· 谁在说话：语音由「小芸本体」发出，不会重复念。
  如果她被你收进托盘（隐藏）了，语音会自动改由聊天窗口播放，不会变成两个声音重叠。

· 系统托盘：右下角托盘里的粉色爱心图标
    显示 / 隐藏小芸 · 打开聊天记录 · 互动模式 · 窗口置顶
    · 回到右下角（找不到她时）· 清空对话记忆 · 退出
    （如果托盘没看到，点托盘区域的 ^ 箭头展开隐藏图标）

  ★ 换声音：「音色（切换声音）」子菜单
    共 6 个女声，点一下立刻换，下一次回复就用新声音（不用重启）：
      晓晓·温暖御姐 / 晓伊·活泼少女 / 晓北·东北口音 / 晓妮·陕西口音
      晓臻·台湾柔嗓（默认）/ 晓雨·台湾少女
    当前生效的那项前面会有勾。选择记在 人设\voice_override.json，
    重启后仍然是它；换人设也不会把音色冲掉（音色是独立设置）。
    试听文件在 人设\试听\音色候选\ 目录里，同一句台词方便对比。

  小提示：拖动不设限制，所以万一把她拖到屏幕外找不到了，
  用托盘菜单里的「回到右下角」就能立刻叫回来。

【常见问题】
· 点她没反应，或者拖不动：
  先确认程序还活着（双击「诊断小芸桌面.bat」看窗口是否存在）。
  若点不动，可以勾选托盘里的「互动模式」用卡片形态操作，再切回去。

· 双击后没反应 / 窗口没出现：
  1) 直接再双击一次「启动小芸桌面.bat」即可。脚本会自动判断"屏幕上到底有没有小芸"，
     如果发现上次退出留下的僵尸进程，会先清理再重新拉起，不需要手动点「停止」。
  2) 仍不行就双击桌面「诊断小芸桌面.bat」，它会逐项检查并告诉你是哪一环没就绪
     （本地大脑 / 后端 / 桌面环境 / 窗口是否真的显示、有没有被切出屏幕）。
  2) 常见原因：桌面窗口组件首次加载要 15～40 秒，看着像没反应，其实在加载。
     请等黑窗口自己走完再判断。
  3) 若桌面窗口实在起不来，脚本会自动改用浏览器打开（同样是这个小芸）。
  4) 排查日志：D:\LunaAI\xiaoyun\desktop_err.log
· 一直“让我想想…” / 她不回话：
  首次回复要加载模型，较慢；之后会顺畅。
  若一直不回，右键托盘的小芸爱心图标看「本地大脑(对话)」那一行：
  显示「未运行」或「在线但没找到模型」时，点下面的「重启本地大脑」即可。
· 找不到 Ollama 的托盘图标：
  正常现象。Ollama 现在以后台服务方式运行，不显示自己的图标，
  状态统一看小芸托盘菜单里的「本地大脑(对话)」。
· 没声音：Edge-TTS 需联网；请联网，并在窗口里点一下允许播放。
· 想完全离线：对话本身离线；只有语音需联网。需要离线语音
  （如 VITS/IndexTTS）属于额外方案，可另行配置。
· 想在浏览器里用（备用方式）：
  浏览器打开 http://127.0.0.1:8090/  是同一个小芸的网页版。
· 后端报错日志：D:\LunaAI\xiaoyun\srv_err.log
· 窗口报错日志：D:\LunaAI\xiaoyun\desktop_err.log

【本地大脑常驻（重要：解决"聊几句就 500"）】

现象：放着不管一会儿，再和小芸说话，后端报 502/500，Ollama 日志里是
      `llama-server process has terminated: exit status 1`。

原因：Ollama 默认「模型空闲 5 分钟就从显存卸载」。卸载后再说话要重新加载，
      而重加载这一步在你机器上（16GB 内存偏紧）容易失败，于是整条对话链断掉。

处理（只需做一次，以后一直有效）：
1. 双击本目录下的「配置Ollama常驻.bat」（务必用普通权限，别用管理员）。
   它会做三件事：
     · 把 OLLAMA_KEEP_ALIVE 设为 -1 —— 模型一次加载后永驻显存，不再被卸载；
     · 把 Ollama 桌面端设置库里的模型目录从空的 C:\Users\...\.ollama\models
       改到真正的 D:\OllamaModels（两边不一致会互相抢端口、找不到模型）；
     · 关掉 Ollama 的自动更新（后台更新会重启服务，表现为"它自己退掉"）。
2. 再双击一次「启动小芸桌面.bat」，让新参数生效（它会自动预热并钉住模型）。

日常自检：
· 双击「诊断小芸桌面.bat」，看到「[OK] 模型常驻显存：qwen3.5-9b ... 到期 2319-...」
  就说明大脑一直在线；到期时间显示 2319 年 = 已被钉住，永不卸载。
· 保活守护：启动小芸桌面.bat 会在后台拉起 Keep-Ollama.ps1，
  每 60 秒巡检一次，服务掉了自动拉起、模型被卸载自动钉回。
  日志：D:\LunaAI\xiaoyun\ollama_keepalive.log

★ 语音对话（2026-10-17 新增）：保留文字聊天，新增"说话就能聊"
============================================================
文字聊天完全不受影响（聊天窗 / 宠物窗该怎样还怎样），新增的能力：

  · 默认就是「连续对话」（宠物窗右下角点标签可切成按键说话）：
      点一下麦克风（或按 Ctrl+Alt+V）→ 按钮变成紫色停止键、提示"🎤 在听…说完停一下"
      → 直接说话，停顿约 1 秒她自动识别并回你，不用再点第二次
      → 她说话时会自动"闭嘴"不收音，不会自问自答；说完自动继续听
      想手动控制就切成「按键说话」：点了才听、再点一次结束。
  · 桌面壳同样有三个入口，透明贴桌面模式下也能用：
      · 托盘右键菜单：🎤 语音对话：按键说一句 / 🎙 连续对话（开关）/ 停止说话
      · 全局热键 Ctrl+Alt+V = 开始/结束说话（不用找按钮，按快捷键就行）
      · 桌面上她右下角那个麦克风按钮，点了同样管用
    ⚠ 为什么按钮要"特殊照顾"：透明桌面模式用分层色键实现透明，
      而 WebView2 在分层色键窗口里收不到鼠标事件（微软已知限制）。
      所以那个按钮的点击是由桌面壳盖的一层"隐形点击层"代劳的
      （页面会把按钮真实位置报给壳，DPI 缩放下也盖得准）。
  · 识别到的文字会先在气泡里显示"我听到：……"，她再接着回

  技术构成（三个进程，各司其职）：
      asr_service.py   → 127.0.0.1:8091  麦克风采集 + 能量VAD + faster-whisper 转写
                         （独立虚拟环境 .venv-asr，CPU + int8，不占显存）
      xiaoyun_server.py → 127.0.0.1:8090  理解与发声（Ollama + edge-tts）
      desktop_app.py   → 桌面窗口 + 托盘

  ⚠ 关于"要不要显存"：
      ASR 默认跑在 CPU 上（int8），显存全部留给 qwen3.5-9b。
      实测：5 秒语音 CPU 上约 2.5 秒出结果，对话完全跟得上。
      OpenRouter 那条路走不通（实测）：免费模型里带音频输入的三个
      （nvidia/nemotron-3-nano-omni、thinkingmachines/inkling(-small)）
      分别要求 $0.50 余额 / 只对编程 Agent 开放，均无法用于普通 API 调用。

  ⚠ 麦克风设备：默认用系统默认输入。要指定（比如 USB 耳麦），在
     Start-Xiaoyun.ps1 里给 ASR 服务加环境变量 XIAOYUN_ASR_INPUT="USB Audio Device"
     （按设备名子串匹配）。

  想换识别模型（更大更准 / 更快）：
      改 Start-Xiaoyun.ps1 里 XIAOYUN_ASR_MODEL 这一行：
        models\faster-whisper-small      464MB  中文良好，CPU 快（当前默认）
        models\faster-whisper-large-v3  2.9GB   中文最好，CPU 慢一些
      两个模型都已下好在 D:/LunaAI/xiaoyun/models/ 下，改完重启即可。

  语音服务没起来会怎样：桌宠右下角提示"语音服务未启动"，文字聊天照常可用。
  日志：asr_out.log / asr_err.log（识别服务）、srv_out.log / srv_err.log（后端）。

★ 出问题时怎么查：前端触发事件日志（新增）
============================================================
每次"点击 / 热键 / 开始听 / 识别 / 回复 / 播放"都记一行，四个来源写进同一个文件：

    D:/LunaAI/xiaoyun/前端事件日志.txt

  前缀含义：
    [页]  宠物网页（desktoppmx.html）里发生的触发
    [壳]  桌面外壳（desktop_app.py）：麦克风按钮层点击、全局热键、收发结果
    [后端] xiaoyun_server.py：/api/voice/* 的每次调用与结果
    [ASR] asr_service.py：会话状态跃迁 + 每 2 秒一条"听"心跳

  典型排查：
    1) 点了没反应 —— 连 [壳] 麦克风按钮层被点击 都没有？
       说明点击没落到按钮层上（位置偏了）。看有没有 [页] 上报麦克风按钮位置。
    2) 说了没反应 —— 看 [ASR] 听 那行的 peak 和 阈值：
       peak 长期远低于阈值 = 声音够不到触发线（麦克风太轻 / 阈值偏高）。
    3) 说完不回 —— 看有没有 [ASR] 转写完成；有转写却没 [后端] 收到识别文字 = 卡在后端。
    4) 热键时灵时不灵 —— 搜 "Ctrl+Alt+V 注册"：
       注册失败会写明"可能被其它程序占用，将自动重试"（每 20 秒重试一次）。
    5) 说了话、也转写出来了，她就是不回 —— 关键判据：
       只有 [ASR] 转写完成 而**没有** [后端] 收到识别文字 = 后台消费者没接手。
       再看 /api/voice/state：若 state 长期停在 pending，就是这种情况。
       （旧版确有此 bug：ASR 服务重启后它内部的 seq 会从 0 重新计数，而后端的判重
         记录还留着上一次的值（如 2），于是新会话里 seq<=2 的转写**全部被静默丢弃**
         —— 日志里连"收到识别文字"都不出现。现已改为不靠 seq 判重，并加了消费者
         看门狗：线程若不在会自动拉起，日志会写"语音消费者线程不在，已自动重启"。）

★ 点麦克风却弹出聊天窗 / 点了没反应 / 桌宠卡死
============================================================
这三件事过去反复出现，根因都已找到并在代码里从根上修掉。判据全在事件日志里。

判据一：搜 [壳] 按下（屏幕
    每次按下都会**无条件**记一行，含命中结果和坐标新鲜度，例如：
      按下（屏幕 2443,1242）命中=mic mic区=(2405,1206,77,77) 坐标上报于0.6s前
    · 命中=mic / mode  → 点对了，动作会照常触发
    · 命中=身体区      → 点偏了；此时如果点位其实在按钮上，就是坐标漂移
    · 找不到这一行     → 点击根本没到达点击层（窗口被别的窗口压住，或进程卡死）

判据二：坐标新鲜度
    "坐标上报于 x.xs前" 里的 x 应该始终 < 1s。数值很大（或 mic区=None）说明页面
    坐标没上来，命中区就是过时的，必然点不准。

判据三：是否卡死
    任务管理器里 pythonw 内存只有 8MB，或窗口标题出现 "(未响应)"，即为卡死残留。
    跑一次 Stop-Xiaoyun.ps1 再 Start-Xiaoyun.ps1 即可（启动脚本已内置自动清场，
    会按命令行把所有残留实例一并清掉，不会再积压）。

------------------------------------------------------------------
根因一：麦克风按钮会被"状态文字"推着横移（已修）
  页面上那排语音控件是"收缩宽度、子元素居中对齐"的容器 —— 状态文字一变长，
  容器就变宽，麦克风按钮被一起推走约 40 像素（125% 缩放下≈49 物理像素）。
  而桌面壳盖在上面的隐形点击层用的是页面上报的坐标，位置一漂就对不上：
  你点的明明是按钮正中心，却被判成"点了她的身体"，于是弹出聊天窗。
  修法：① 控件改为右对齐（每个元素的右边缘锚在同一条固定线上，互不影响）；
        ② 坐标从"只在加载时报一次"改为每 0.6s 常驻同步；
        ③ 壳侧再加 16 像素的近似命中容差兜底。
  现在的按钮位置是**固定**的（CSS x=606），日志里不会再出现 Δx 漂移。

根因二：坐标上报曾经走 pywebview 的 JS 桥，把窗口堵死（已修）
  JS 桥是"同步回环"调用，要在桌面壳的主线程上执行。页面按固定频率推坐标时，
  会把 WebView2 的界面线程堵死 —— 表现就是"桌宠卡死"（窗口变"(未响应)"），
  并且 Windows 会为它生成一个 dwm 的"Ghost 替身窗口"盖在原地，把该区域所有
  点击都吃掉（于是又卡又点不动）。
  修法：坐标改走**本地 HTTP**（/api/ui/rects），与壳的消息循环彻底解耦。
  页面的触发日志本来就一直走 HTTP、从未出问题 —— 现在是同一条通道。
  顺带：页面判断"有没有壳"改看后端心跳（/api/shell/beat），不再猜 JS 桥的时序。

★ 麦克风太轻、喊了也不触发？调 VAD 灵敏度
============================================================
先用项目自带电平计量一下你的麦克风（对着它正常说一句话）：

    D:/LunaAI/xiaoyun/.venv-asr/Scripts/python.exe D:/LunaAI/xiaoyun/tools/麦克风电平检测.py 8

  它会打印每一段 0.5 秒的 RMS。把"峰值"和下面的触发阈值比一比。

触发线 = max(阈值下限, 环境噪声 × 倍数)，这两个都能在 Start-Xiaoyun.ps1 的 ASR
环境变量里调（改完重启语音服务生效）：

    "XIAOYUN_ASR_THR"     = "0.001"   # 阈值下限，越低越灵敏
    "XIAOYUN_ASR_NOISE_K" = "1.3"     # 噪声倍数的系数（3.2 偏保守，会把下限顶上去）

  ★ 关键：光把下限写小往往没用 —— 触发线取的是"下限"和"噪声×倍数"里**更大的那个**。
    本机 USB 麦的噪声底约 0.0007，倍数 3.2 时实际触发线被顶到 0.0022，下限写多小
    都不生效；把倍数降到 1.3 之后，生效值才真的是 0.001。事件日志 [ASR] 听 那行
    会打印**当前真实阈值**，改完一律以它为准。

  ★ 想降阈值提高灵敏度，必须先把"最大的误触发源"堵住，否则一降就变成她自问自答：
    她自己的播放声经音箱回授后可达 0.0023~0.0112，和你的说话声**量级完全重叠**，
    靠阈值是分不开的。项目已保证"她播放回复期间不收音、真正播完才恢复"
    （播放时长由页面上报真实值；事件日志里会写"页面已报播完，但按上报时长还差
    x.xs，延迟恢复收音"——看到这句说明这道闸在起作用）。

★ 重复点启动图标会怎样？（已做防护）
============================================================
以前会出问题，现在不会了。原因值得知道：

三个服务的"已经在跑吗"判据都是"**服务能应答 / 窗口出现了**"，而**正在启动中**的
服务既不能应答、也没有窗口 —— 于是第二次点启动会以为"没在跑"，再起一个：
  · 两个后端（Windows 允许两个进程绑同一个端口）-> 两个语音消费者抢同一条转写，
    她可能重复回话；
  · 两个语音识别服务 -> 同时抢麦克风，语音时好时坏；
  · 第二个启动还会把**第一个正在加载的桌面窗口杀掉重来**（清场那一步），
    表现就是"启动特别久、好像起不来"。

现在 Start 和 Stop 共用一把**单实例锁**（Windows 命名互斥量 XiaoyunCtrl）：
若已有一次启动/停止在进行，第二次启动会直接提示
"已有一个启动/停止流程在进行中，等它完成即可（本次不重复启动）。"并退出，
启动日志里会留一行 [跳过]。

另外 Stop-Xiaoyun.ps1 这轮也补齐了两件事：
  · 兜底清理现在**包含后端**（以前只按端口杀，后端若没在监听就漏掉了）；
  · 停止后新增 **[复核]** 段：逐项检查 8090/8091 是否释放、有无残留进程、
    窗口是否关闭，并特别检查有没有「小芸 (未响应)」Ghost 替身窗口。
    以前是杀完就直接报 [OK]，无从确认。

日常用法不变：启动点 Start-Xiaoyun.ps1，停止点 Stop-Xiaoyun.ps1。
重复点也不用担心，第二次会被锁挡下。
